# Отчёт по рекламным каналам

В этом примере руководитель открывает недельный отчёт по постоянному адресу. Сотрудник уже собрал отчёт вручную. Его результат и копии исходных записей пригодятся для проверки процесса в n8n.

## Данные за неделю

Период начинается в понедельник 16 ноября 2026 года в 00:00 по Москве и заканчивается перед следующим понедельником. Статусы заявок сотрудник проверил 23 ноября в 09:00 по Москве.

| Файл | Что в нём |
| --- | --- |
| [visits.json](visits.json) | Учебный ответ API Метрики с числом визитов по каждому источнику за весь период |
| [leads.csv](leads.csv) | Семь строк со временем поступления заявок и взятия в работу в UTC. Две строки лежат за границами отчётной недели |
| [reference-report.json](reference-report.json) | Отчёт сотрудника с контрольными строками и итогом за неделю |

В n8n откройте **Data tables** своего проекта и импортируйте копию _leads.csv_ в новую таблицу с именем `analytics_leads`. Для всех четырёх столбцов выберите тип String. Колонка `leadId` хранит номер заявки, `utmSource` содержит метку источника, `submittedAt` обозначает время поступления, а `takenAt` заполняется, когда менеджер берёт заявку в работу. При отсутствии такого события поле остаётся пустым.

## Запуск страницы

Из корня проекта выполните команду.

```sh
docker compose -f compose.yaml -f analytics/compose.yaml up -d --wait
```

n8n откроется по адресу `http://127.0.0.1:5678`, страница руководителя по адресу `http://127.0.0.1:8002/`. До публикации первой сводки на странице будет сообщение об ожидании отчёта.

В ноде HTTP Request используйте адрес `http://report:8000`. Оба контейнера находятся в одной сети, и имя `report` указывает на сервис страницы. Учебный снимок визитов доступен по пути `/visits.json` и относится только к неделе с 16 по 22 ноября. Для другого периода подключите свой счётчик Метрики.

## Публикация отчёта

Отправьте полученную сводку методом POST на `/reports` с типом тела JSON. Входные поля показаны в _reference-report.json_. Границы недели `periodStart` и `periodEnd` записываются датами двух соседних понедельников, причём дата окончания в период не входит. В `rows` лежат строки каналов, в `total` общий итог. Пустое значение `per100` передаётся как JSON `null`.

После успешной записи сервис вернёт сводку и время публикации `updatedAt` в UTC. Обновите страницу руководителя, чтобы увидеть её. Сервис хранит последнюю успешную версию каждой недели. Повторная отправка за ту же неделю заменяет запись целиком. Страница показывает сводку за самую позднюю неделю, даже если после неё сотрудник пересчитал более старую.

- `GET /reports/latest` отдаёт ту же сводку, которую читает страница.
- `GET /reports/2026-11-16` возвращает результат за выбранную неделю.
- `POST /alerts` принимает учебное уведомление с границами недели `periodStart` и `periodEnd` и причиной сбоя в `reason`. В поле `asOf` можно сохранить время сверки статусов заявок. Дежурный может посмотреть уведомления по адресу `http://127.0.0.1:8002/alerts`. Свежие сообщения идут первыми.

Ошибку чтения источника можно воспроизвести, временно заменив в ноде адрес `/visits.json` на `/missing`. Сервис вернёт HTTP 404. После исправления адреса доступ к снимку восстановится.

Для остановки выполните команду из каталога проекта. Опубликованные отчёты и уведомления останутся в томе Docker.

```sh
docker compose -f compose.yaml -f analytics/compose.yaml down
```
