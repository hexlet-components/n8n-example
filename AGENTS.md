# AGENTS.md

Компонент даёт студенту программы «AI-автоматизация» свой n8n: локально в Docker (`compose.yaml`) и на машине в Яндекс Облаке (`deploy/cloud-init.yaml`). Им пользуются самостоятельные работы курса n8n, решение от 23.11.2026. README написан для студента.

## Проверки

Перед тем как считать изменение готовым, пройди `mise run check` и `mise run test`. Обе команды идут в CI. Тесту нужен Docker.

## Версия n8n

Версия n8n записана в двух местах: образ в `compose.yaml` и образ внутри `deploy/cloud-init.yaml`. Образ берётся с Docker Hub (`n8nio/n8n`), потому что Dependabot не ходит в реестр `docker.n8n.io`. Образы в обоих реестрах совпадают по digest. Меняются они одним коммитом, `mise run test` падает при расхождении. Dependabot поднимает только `compose.yaml`, поэтому его PR зелёным не станет, пока версию в `deploy/cloud-init.yaml` не поднимут рукой.

`deploy/cloud-init.yaml` проверен на живой машине в Яндекс Облаке 18.11.2026. Изменение в нём проверяется созданием машины, схема cloud-init ловит только синтаксис.

## Контрольные точки

`seeds/<слаг урока>/` хранит сценарии курса n8n (`hexlethq/courses/ru/n8n_course`) в состоянии к началу этого урока. Сценарий повторяет пример из теории урока. Решения самостоятельных работ и проекта в точки не попадают, иначе компонент раздаёт ответы.

Сквозной сценарий держит один id во всех точках, поэтому загрузка следующей точки заменяет предыдущую. Каждая точка получает ожидание `test/expected/<слаг урока>.json`: какую ноду проверить и какие поля её первой записи сравнить. Тест запускает сценарии, которым не нужны подключения и сеть. Точку меняют тем же заходом, что и пример в уроке.

## Исключения

Правила проверок не отключаются ради прохождения. Исключение узкое, с причиной, и его принимает человек.
